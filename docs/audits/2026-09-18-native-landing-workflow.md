# Native landing workflow audit

The public landing now builds from `site/index.html` through the same `moss build site` invocation as the documentation. This removed the temporary post-build overlay and custom server from the shipping path.

## Friction observed

- `moss --help` clearly exposes `build --serve --watch`, but neither the help nor `moss describe --json` exposed the `[build].passthrough` setting. `describe` contains no config schema and its output has no `passthrough` string. The bounded improvement is a source-owned homepage recipe in the bundled authoring guide and the exact public-site commands in `scripts/README.md`; a discoverable config-schema contract remains future work.
- A cold build paused for 118 seconds after `Building website from: site` and printed no phase progress; the warm scan took 52 ms and the full warm build took 7.2 seconds. The silence made a slow metadata/cache start indistinguishable from a hung build.
- `moss build site --strict` generated a complete site but exited 1 because this checkout has no live deployment record. Passing `--site-url=https://mosspub.com` did not change that diagnostic. Local preview therefore uses the supported ordinary build command and leaves the warning visible.
- Declaring video-bearing scene directories as passthrough exposed a build bug: the video worker correctly excluded them, but the deferred asset copier also skipped every video, so the MP4 files disappeared. The copier now owns videos inside passthrough directories, with a regression test.
- The former workflow treated a successful route response as enough evidence. A custom server rewrite returned 404 for hashed CSS and JavaScript URLs, so documentation HTML loaded while rendering without styles. `scripts/check-site-preview.mjs` now rejects missing assets and HTML fallbacks by verifying response types and representative content for same-origin CSS and JavaScript as well as the route contract.
- The native preview passed the checker for 14 pages and 9 same-origin CSS and JavaScript assets. Chromium and WebKit also rendered the landing plus English, Simplified Chinese, and Traditional Chinese documentation with styles. Full-motion checks in both engines also verified that Scene 3 and Scene 5 videos loaded and advanced through the native server. The only observed network failure was the harvested demo fixture's `/__moss/token` authentication probe; cleaning that fixture is follow-up work rather than a native-server endpoint.
- Native builds rewrote `site/.moss/.gitignore` and removed 199 tracked files from the obsolete `site/.moss/build/site` tree. Build output is now ignored as a whole and removed from version control, so a normal build/watch cycle no longer dirties the source checkout with generated output.

## Watch failures found through real edits

The native editing check uncovered several independent failures. HTML source extensions were absent from the watch filter; relative CLI roots such as `site` did not match absolute filesystem notifications; and an edit restored during a build could be recorded in the final source hash baseline even though output still contained the earlier edit. The hash baseline also predates deferred HTML/JavaScript/media copying, making it unsafe to suppress those asset events. The fixes add HTML to the source filter, canonicalize the initial headless session and watch root together, limit the hash gate to Markdown, and force a catch-up build for requests received during an active build. Generated `.moss` HTML remains outside the watch boundary. Default logs initially made the missing update look like a stalled rebuild; `MOSS_LOG_LEVEL=debug` showed that builds completed while the hash gate discarded later source events. The bundled debugging guide now states the correct CLI logging variable and default.

The regression procedure changes `site/index.html`, `site/closing.js`, and `site/Get Started/Meet the editor.md` one at a time, verifies each marker through the running native HTTP server, restores the original source immediately, and verifies the marker disappears. This tests the editing workflow itself rather than merely checking initial build output.

Final verification passed all three edit-and-restore cases through `moss-cli build site --serve --watch` using the relative `site` argument. All source markers were removed. The preview checker passed again after restoration.
